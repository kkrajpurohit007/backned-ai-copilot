# Evaluate engineering options and record decisions

## When to use
Use when selecting a design, pattern, library, or architecture.

## Workflow
1. Define decision, constraints, and success criteria.
2. Identify viable options including doing nothing.
3. Compare correctness, complexity, performance, security, operability, cost, and reversibility.
4. State assumptions and risks.
5. Recommend an option with rationale.
6. Create a concise ADR with context, decision, consequences, and alternatives.

## Evidence and safety
Use repository paths and symbols as evidence. Do not invent details or reveal secrets. Mark verified facts, inferences, assumptions, and unknowns. Remain read-only unless implementation is explicitly requested.

## Expected output
A concise, evidence-based analysis with findings, risks, next steps, and validation appropriate to the task.
