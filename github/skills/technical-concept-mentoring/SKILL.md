# Teach engineering concepts through current repository work

## When to use
Use when the user asks why/how or a task reveals an important concept.

## Workflow
1. Identify the concept directly relevant to current task.
2. Explain what it is, why it exists, and the problem it solves.
3. Connect to actual repository evidence.
4. Explain alternatives and trade-offs.
5. Cover common mistakes and production considerations.
6. Add a small exercise or interview check if useful.
7. Scale from fundamentals to senior/staff/principal without unrelated overload.

## Evidence and safety
Use repository paths and symbols as evidence. Do not invent details or reveal secrets. Mark verified facts, inferences, assumptions, and unknowns. Remain read-only unless implementation is explicitly requested.

## Expected output
A concise, evidence-based analysis with findings, risks, next steps, and validation appropriate to the task.
