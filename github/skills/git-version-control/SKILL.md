# Choose safe Git workflows and recover changes

## When to use
Use for branching, history, conflicts, or lost/uncommitted work.

## Workflow
1. Inspect status, branch, and relevant history first.
2. Determine whether changes are local or shared.
3. Explain merge/rebase/cherry-pick/revert/reset implications.
4. Prefer non-destructive recovery.
5. Require approval for destructive commands or remote history rewriting.
6. Provide verification and recovery steps.

## Evidence and safety
Use repository paths and symbols as evidence. Do not invent details or reveal secrets. Mark verified facts, inferences, assumptions, and unknowns. Remain read-only unless implementation is explicitly requested.

## Expected output
A concise, evidence-based analysis with findings, risks, next steps, and validation appropriate to the task.
