# Analyze performance and telemetry

## When to use
Use for latency, throughput, resource, or observability concerns.

## Workflow
1. Define measurable symptom and baseline.
2. Inspect metrics, traces, logs, profiles, and code paths.
3. Analyze database, network, pools, concurrency, CPU, memory, and cache.
4. Separate evidence from hypotheses.
5. Recommend targeted experiments, instrumentation, and alerts.
6. Avoid optimization without measurements.

## Evidence and safety
Use repository paths and symbols as evidence. Do not invent details or reveal secrets. Mark verified facts, inferences, assumptions, and unknowns. Remain read-only unless implementation is explicitly requested.

## Expected output
A concise, evidence-based analysis with findings, risks, next steps, and validation appropriate to the task.
